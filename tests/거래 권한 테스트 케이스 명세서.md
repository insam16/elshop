# 거래 권한 테스트 케이스 명세서

## 📌 전제 조건
- ADMIN은 거래 참여 불가
- USER: 인증 유저
- TEMP: 미인증 유저
- 정책:
  - 연락처 보기: USER만 가능
  - TEMP는 연락처 조회 불가
  - 연락처 조회 시 게시글 상태 변경

---

## 📌 게시글 상태 정의
- ACTIVE: 거래 가능
- RESERVED: 예약 중. 연락 진행 중
- COMPLETED: 거래 완료
- EXPIRED: 거래 시간 만료

## 🔥 예외/리스크 케이스

### 1. TEMP 다수 참여
- 케이스: 4, 7, 8
- 대응:
  - UI 경고 표시
  - 필요 시 LOCKED 전환 고려

---

### 2. 판매자가 TEMP
- 케이스: 5, 6, 7, 8
- 대응:
  - 구매자에게 "미인증 판매자" 경고 표시

---

### 3. 동시 조회 경쟁 상황
- 구매자1, 구매자2가 동시에 USER인 경우 (1, 5)
- 확인 필요:
  - 선점 구조인지?
  - 둘 다 RESERVED 허용인지?

## ✅ 추가 테스트 포인트

- 연락처 조회 API 권한 검증
- 중복 조회 방지 (1회 제한 여부)
- 상태 변경 race condition
- TEMP → USER 전환 시 동작

---

## 💡 한 줄 정리
- USER만 연락처 조회 가능
- 조회 시 거래는 "RESERVED" 상태로 전환
- TEMP는 조회 불가 → 상태 변화 없음
